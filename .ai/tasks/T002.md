### §1 Engagement unit — 확장
`sec_definition.tex`의 **현재(v3.3) 정의**만 옮긴다. 각 상수 뒤에 괄호로 출처 절을 적는다(`[sec_definition §G]` 형식).
- **킬 에피소드와 G:** 연속 킬 간격 ≤ G → 같은 에피소드. G = 로그 킬 간격 분포의 antimode(KDE valley, 2-성분 GMM으로 측 결정). Ĝ = 13.7246 s, 검출기 실행값 G = 13.700 s, 경기 부트스트랩 95% 12.2–15.7 s; gap 10–18 s 어디서나 ARI ≥ 0.9. [§G]
- **공간 분할과 D:** 에피소드 안 두 킬 거리 > D이면 분할(first-fit). D = 연속 킬 쌍의 챔피언 공유율이 0.5가 되는 거리. D̂ = 4,263.87 u, 실행값 4,264.0 u, CI 4,256–4,274 u. [§D]
- **Presence gate (R, B, M):** τ = 첫 킬 시각 − B (B = 15 s). τ에서 첫 킬 위치(anchor) 반경 R = 1,600 u 안에 **양 팀 각각** M = 2명 이상 생존해야 engagement. 생존은 τ 직전 1분 프레임, 위치는 5 s 격자 보간. R·B는 게임 규칙 앵커(경험치 공유 반경, 어시스트 창)로 고정, M은 관례. [§Presence gate]
- **라벨 귀속 창·디스크:** \([\tau,\ \max(t_{\text{lastkill}}+1\,\text{ms},\ \tau+H))\), H = 35 s, ace 시 조기 종료; anchor 중심 반경 D 디스크 안 사건만. [§Which events]
- **패치별 재추정:** 15.14/15.15/15.16 각각의 G·D가 pooled plateau 안 → pooled 정의 사용. [§Re-estimation]
- **규모 계급:** 참여자 수 n_min 기준 pick ≤ 1 / skirmish 2–3 / teamfight ≥ 4. 이 논문의 예측 표본 **T**는 teamfight 계급이며, 실제 코호트 구성은 2026-09-15 cohort role build의 `cohort == 1` 플래그로 고정된다. [§Scale classes; `rr20260920_q_build_newv_labels.py` `cohort_keys`]
  - **주의:** sec_definition의 532,547 / 109,829 계열(208,141경기 코퍼스)과 pooled T 113,901(210k 코퍼스, T ∩ valid_h90)은 코퍼스·필터가 다르다. 한 표에 넣지 않는다. T의 정확한 자격 규칙 문장(참여자 산정 방식, 추가 필터)이 이 브랜치 `docs/`에서 확인되지 않으면 `\pending{T-rule}`로 남기고 보고.
- **engineering 상수 소표:** `tab:constants`(L451–L641)에서 재교전 merge, duration cap, 시작·종료 제외, interaction radius, dead zone 등의 **값과 출처 분류(Data-derived / Rule anchor / Convention / Engineering)**를 그대로 옮긴 표 하나. 값을 tex에서 읽어 적고, 읽히지 않는 셀은 `\pending`.
- **분리 규칙:** conference-era·소규모 파일럿 민감도(anchor-vs-centroid 2,971경기, shop-event 3,000경기, kill/structure winner 5,000경기, H 파일럿 553경기, G×D sweep 10,000경기 등)는 본문에 옮기지 않는다. 절 끝에 한 문장만: `Sensitivity of secondary constants was measured on conference-era or pilot corpora and is documented in the definition lineage (docs/tog_manuscript/sec_definition.tex); it has not been re-run under the current corpus.`

### §2 Frozen evaluator — 절차 보강
- 입력: Expanded361 = 351 numeric + 10 champion-ID slots; 임베딩 MLP는 챔피언 ID를 8차원 임베딩(vocab 172, index 0 = UNK)으로 바꿔 351 + 10×8 = 431 입력. [meta json `preproc_dims`; `BAND_LEDGER_WAVE4` winner 문단; `fit_wave4_corrected.py` `fit_mlp_emb(emb_dim=8, hidden=(256,128), dropout=0.1, seed=7)`]

- 학습: TRAIN 경기 85/15 홀드아웃(seed 7)으로 early stop; full-TRAIN 재적합 없음 (`fit_scope: train_fit85_match_holdout_frac0.15_seed7_NO_full_train_refit`).

- 선정: V_SELECT에서 \(L_{\mathrm{time}}=\sum_b \alpha_b\,\mathrm{Brier}_b\), \(\alpha_b=1/4\), 밴드 [2,10), [10,20), [20,30), [30,∞) 분; t < 2분 제외. [`V_NEXT_RUN_EXECUTION_CONTRACT`; RR design §6]
- 경쟁 후보(GRU 등)는 "point estimate only; single seed" 문구로만 언급, 우열 주장 금지. [`BAND_LEDGER_WAVE4`]

### §4 Direction predictor and baselines — 보강
- \(q\) = `logit_state`: StandardScaler + L2 logistic on 351 numeric pre-state features + \(p_{\mathrm{pre}}\) (352 inputs; raw champion IDs excluded). `lgbm_state` 후보는 챔피언 ID 10개를 범주형으로 포함(362 inputs) — 동일 입력 비교 아님. [`q_newv_primary_fit.py` L185–L225]
- 선정: Q_SELECT 경기 가중 Brier; Q_CAL은 LGBM early stopping에만 사용; \(q\)/PT_flex의 확률 보정기는 Q_SELECT에서 identity 선택. [Q contract §3; RR12 json `calibrator_choice`]
- PT_flex: \(p_{\mathrm{pre}}\)·time 각각 cubic B-spline(`SplineTransformer`, uniform knots, `include_bias=False`, `extrapolation="constant"`) + 두 기저의 전 tensor 곱 → StandardScaler → L2 logistic (lbfgs, `sample_weight=1/n_m`). 탐색 격자 n_knots_p ∈ {4, 6} × C ∈ {0.01, 0.1, 1}; n_knots_t = 4 고정; 선택 (4, 4, 0.01, degree 3). 설계서의 가중 분위수 knot·평균-1 가중 정규화·공동(설정×보정기) 선정은 **실행되지 않았음** — 실행 addendum 문구를 따른다. [`rr12.py` `PTFlexFeatures`, `fit_pt_flex`; `RR1_EXECUTION_ADDENDUM`; RR12 json `PT_flex`]
- \(b\)-spline: \(p_{\mathrm{pre}}\) 단독 cubic spline (n_knots 6, C 0.01). PT_linear: StandardScaler + logistic on \([p_{\mathrm{pre}}, \text{time\_minutes}]\).
