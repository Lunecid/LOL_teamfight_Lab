# Task 8 GPU 비용 측정과 코드 정리 작업 계약

2026-10-24 저자는 깨끗한 실행 폴더에서 남은 GPU 비용 측정을 진행하고, 기존 S CPU 결과를 보존하며 결과별 보고서·시각화를 만들고 G-S4a에서 멈추라고 승인했다. 아키텍처에서 필요 없는 정크 코드 정리도 함께 요청했다.

## 승인된 측정 범위

- S와 M, CUDA만, 모델별 최대 2에폭, FIT/STOP 25%, DEV 최대 200행, 기존 합성 S=200, batch 32와 기존 seed/float32/결정성·예산 계약 유지.
- 기존 v1 전체 CPU/CUDA operator는 그대로 두고 명시적인 v2 gpu_cost profile을 추가한다. v2는 cuda만 허용한다. 기존 Check/Start/Resume/Status, 전체 Git 청결, E6, 입력·환경·설정·코드 identity, 24h/40GiB 경계는 유지한다.
- 기존 실패 run을 Resume하지 않는다. 새 run과 새 identity를 만든다. 기존 S CPU 측정·실패 기록·가중치와 입력은 수정하지 않는다. old stage를 새 연속 실측으로 재등록하지 않는다.
- 새 소스에서 scales/stats를 기록하고 S CUDA, M CUDA, infer, compose, project를 수행한다. CUDA 실행 프로필 완료는 원래 CPU 포함 전체 격자 완료와 다르다. M CPU는 이번 범위에서 미측정이다.
- 기존 S CPU는 다른 커밋의 역사적 참고 실측으로 표시한다. 새 CUDA와의 비율을 통제된 동일 코드 속도 향상이라고 부르지 않는다.

## 실행·보고

구현과 독립 검토를 분리한 뒤 커밋을 고정하고 별도의 깨끗한 실행 checkout을 만든다. 제어·설정·보고 파일은 그 checkout 밖에 둔다. 실행 중 코드·문서·환경 파일을 바꾸지 않는다. 개발자 로컬 주석 20개가 남아 있는 IDE 폴더는 실행용으로 쓰지 않는다.

작은 metadata watcher로 새 실제 완료 단계·실패만 확인한다. 각 완료 단계의 root JSON·STAGES·RUN 해시를 검증하고 버전별 한국어 보고서·표·JSON·상태 SVG를 만든다. 실행 중에는 무거운 수치 렌더링을 하지 않는다. 종료 뒤 전체 숫자 그림을 렌더링하고 실제 그림과 원본 수치를 대조한다. private 표본, lifetime upper, GPU allocator를 구분하고 중첩 시간·미측정·조건부 외삽·회복 측정의 한계를 표시한다.

G-S4a에서 보고 장치·모델 크기·다음 에폭 예산·S4b 범위를 저자에게 제시하고 멈춘다. S4b/S6/S7 또는 M CPU를 자동 시작하지 않는다. 실패 시 부분 실측과 원인을 보고하고 멈춘다. Strata는 계속 OFF다.

## 정크 코드 정리

검토된 GPU 실행 커밋과 별개인 개발 트리에서 정리한다. 단순히 오래됐거나 이름이 legacy/compat라는 이유로 지우지 않는다. 현재 import·CLI·packaging·동적 참조·과거 검증/재현에서 필요한 코드는 보존한다. 원고·잠금 결과·보호된 분할·원시 자료·가중치·사용자 변경은 삭제 대상이 아니다.

Git 추적 파일과 진입점·참조를 조사해 삭제 후보·이유·파일 수·크기를 먼저 고정한다. 필요성이 없는 vendor/실험성 도구 사본·확실한 죽은 코드·생성 잔여물만 제거하며 관련 참조를 정리하고 제한 검증·독립 검토를 거친다. 단순 전역 텍스트 검색 0건만으로 동적 Python 모듈을 삭제하지 않는다. 실행 폴더에는 정리를 반영하지 않는다. GPU 측정과 동시 호스트 활동이 있으면 시간·종류를 기록한다.
