# 세 프로젝트 모듈화 작업 계약

## 승인과 기준선

2026-10-24 저자는 현재 EPT, CoG, Master 코드의 모듈화·프로젝트화·최적화,
설계/코드 검사, 부품화 이후 Gemini 주석 작업, 완료 후 Git 커밋과 푸시를 요청했다.
이 요청은 이 브랜치의 코드 변경과 게시를 승인한다. 연구 정의 변경이나 추가 실험의 승인은 아니다.

- 기준 커밋: `282dcc36f2e175b33782fc0b4bcb31581e663612`
- 작업 브랜치: `codex/modularize-three-projects`
- 현재 Task 8 실행 폴더와 `c-ept/s4` 체크아웃은 변경하지 않는다.
- 다른 작업자가 남긴 주석 변경은 원래 작업 공간에 보존한다. 이 브랜치로 무조건 가져오거나 되돌리지 않는다.
- COG의 논문/동결 수치, Master의 원본 작업 공간/날짜별 근거 경로, 입력/분할/라벨/가중치는 변경하지 않는다.

## 구현 경계와 이유

1. **EPT 실행 기반**: S3 실행기의 비공개 자원 감시 코드를 공통 런타임으로 분리한다.
   S3/S4는 공개 부품을 사용하며 기존 호출의 호환 표면을 유지한다.
2. **EPT 저장과 학습**: 검증된 체크포인트 읽기/쓰기, 학습 계산, 실행 회계를 분리한다.
   스키마·난수·best/last 선택·재개·손상 거부·24시간/40GiB 검사 계약을 유지한다.
3. **EPT 선택 계산**: 시작률만 필요한 평가 경로에서 사용하지 않는 mark/zone 계산을 제거한다.
   학습의 dropout 난수 소비가 달라지는 최적화는 별도 근거 없이 적용하지 않는다.
4. **프로젝트 경계**: EPT, CoG, Master에 구별되는 배포/진입점과 문서를 둔다.
   CoG/Master의 일반적인 최상위 패키지를 같은 환경에 설치해 덮어쓰는 문제를 막는다.
   기존 연구 진입점과 과학 정의를 보존하고 source-backed 실행의 요구 경로를 명시한다.
   CoG의 순수 fusion 명세 해석과 Master의 순수 sigmoid/logloss를 분리하되 기존 이름은 재노출한다.
   보정기 클래스의 pickle 경로는 옮기지 않는다. 복사된 새 소스는 새 코드 버전이며 과거 실행 재개의 근거가 아니다.
5. **주석**: 새 부품/변경 API의 목적·수식·단위·경계·호환성을 실제 코드에 맞춘다.
   Gemini는 사용자 정정에 따라 OpenCodex를 통해 요청한다. 연결 실패는 사용한 것으로 기록하지 않는다.
   기존 수식 등록부와 과학적 의미를 유지하고, 주석만의 변경은 AST 동등성으로 점검한다.

## 역할

Sol 6.1 구현 작업자는 서로 겹치지 않는 파일 집합을 맡는다. Codex는 설계와 통합,
별도 독립 검토와 최종 수용을 맡는다. 구현자의 자체 시험을 독립 검토로 부르지 않는다.
Strata는 꺼둔다. Gemini에 비밀정보, 원시 데이터, 체크포인트, 분할 모듈 본문을 보내지 않는다.

## 수용 기준

- 새 공통 부품이 상위 실행기/학습 조정기에 의존하지 않는다.
- 기존 CLI/체크포인트 계약과 오류 거부가 유지된다.
- 최적화한 평가 출력이 원래 출력과 일치하고 사용하지 않는 계산이 실제 생략된다.
- CoG/Master 진입점은 import/help만으로 연구 실행을 시작하지 않는다.
- 합성 입력의 회귀 시험, 오류 경로 시험, 패키지 경계 검사와 별도 검토를 통과한다.
- 실측 속도 개선은 동일 조건의 측정 없이는 주장하지 않는다.
- 검사 범위와 남은 위험을 보고한다. 유한한 검사로 프로젝트 전체의 무오류를 보증하지 않는다.
- 현재 비용 측정과 겹치는 무거운 시험/벤치마크는 실행하지 않는다. 필요한 검증을 못 마쳤으면
  완료/최종 게시로 표시하지 않는다.

## 게시

수용된 변경과 필요한 문서/시험만 위 브랜치에 커밋하고 기존 `origin`에 일반 push한다.
다른 브랜치에 강제 push하거나 실행 중인 브랜치를 병합/재설정하지 않는다.
원고·데이터·로컬 인증·실험 산출물은 게시 대상이 아니다.
