## 판정

v3의 연구 방향은 일관되지만, v3.2를 최종 기준 결과로 확정하기 전에 구현 결함과 측정 계약을 보완해야 한다. 특히 라벨 끝점의 마지막 킬 누락은 결과 라벨에 직접 영향을 준다. 현재 AUC의 편향 크기나 방향은 아직 측정하지 않았다.

## 1. [P1, 확정] 긴 교전의 마지막 킬이 라벨에서 제외될 수 있다

- `gameplay/fights.py:1398`은 `fight_end_ts = last_kill_ts + tail_buffer_ms`, `horizon_end_ts = max(fight_end_ts, engage_ts + horizon_ms)`로 끝점을 만든다. 현재 tail buffer는 0이다.
- `gameplay/fight_postmerge.py:33`은 끝점을 exclusive로 취급하고 `data/events_index.py:177`은 `[s, e)`로 사건을 가져온다.
- 따라서 마지막 킬이 최소 horizon 끝 이상일 때 끝점과 같은 마지막 킬이 빠진다. 이후 정리 단계에서 창이 달라진 표본은 별도 추적해야 한다.
- 합성 재현: cutoff=5,000ms, 첫 킬=20,000ms(블루 +400), 마지막 킬=41,000ms(레드 +1,000). `compute_label`에 end=41,000을 주면 블루(1), end=41,001이면 레드(0). 가격표는 비워 킬 골드만 비교했다.
- 수정안: 입력 사건 구간의 반열림 계약은 유지하고, 라벨 종료 시각 생성에서 마지막 킬을 포함하도록 exclusive 끝점을 계산한다. 전멸·후속 병합·충돌 정리도 같은 계약으로 통일한다. 전멸 경로에는 이미 `ace_t + 1` 처리가 있다.
- 검증: 마지막 킬과 horizon이 같은 경우/넘는 경우, 동일 ms 다중 사건, 전멸, 후속 병합, 충돌 절단 회귀 테스트. 기존 코퍼스에서 영향 표본 수와 라벨 반전율을 산출한다. cutoff나 표본 선택이 바뀌면 특징도 재구축해야 한다.

## 2. [P1, 확정] 일반 LightGBM 경로에서 특징 이름이 전부 유실된다

- `train/baseline.py:185`의 `infer_tabular_plan`은 기존 통계 열 이름만 반환한다.
- `build_tabular_Xy`는 plan이 없을 때만 `frame_age_s` 이름을 추가하지만, 값은 plan 유무와 무관하게 추가한다.
- 일반 학습 경로는 plan을 사용한다(`:547`, `:555`). 열 개수 불일치 시 `:346`에서 모든 이름을 `f0...`로 대체한다.
- 실제 함수와 합성 캐시 재현: plan 이름 7,105개, X `(1, 7106)`, 최종 이름 `f0`, `f1`, ..., `f7105`.
- 영향: 이름 기반 정적/준상수 특징 제거, 설명 가능성, SHAP 해석이 손상된다. plan을 전달하지 않는 코퍼스 샤드 경로에는 이 재현이 직접 적용되지 않는다.
- 수정안: 특징 값과 이름 생성 규칙을 하나로 합치고, 신선도·모멘텀 등 추가 블록까지 포함해 plan을 만든다. 무명 열로 조용히 진행하지 말고 불일치 시 실패시킨다.

- 수정안: 자식 실패 시 평가 금지, 정확한 샤드 집합 검증, 원자적 파일 저장, 실행 ID·소스 커밋·가격표/지도표 해시·실효 설정·특징 스키마를 manifest에 기록하고 merge에서 일치 확인.

## 4. [P1, 측정 계약] 교전 라벨이 지도 전체의 동시간대 결과를 포함한다

- `gameplay/labels.py:compute_label`은 시간 구간의 모든 사건을 가져온다. 가격판 라벨에는 공간 거리나 해당 클러스터 참여 여부 필터가 없다.
- `_lex_refine`의 “cluster kills”도 첫/마지막 킬 시각으로만 제한하며 실제 클러스터 사건 ID를 쓰지 않는다. 생존자 비교도 양 팀 전체 10명이다.
- 따라서 반대편 라인의 킬·타워·오브젝트가 특정 교전의 승패를 바꿀 수 있다. 데이터 누수와는 다른, 목표 변수의 귀속 문제다.
- 선택지 A: 목표를 “교전이 발생한 시간창의 팀 전체 경제 결과”로 정확히 명명한다.
- 선택지 B: 클러스터 사건/참여자와 연결한 교전 라벨을 추가한다. 전환 오브젝트의 귀속 규칙은 사전에 명시한다.
- 필요한 실험: 전역/클러스터 제한 라벨 불일치율, 원거리 사건 기여율, 규모별 반전율, 공통 표본·고정 fold에서 AUC 비교. 측정 없이 전체 기존 결과가 틀렸다고 단정하지 않는다.

## 5. [P2, 확정] 다중 라벨 비교는 주 라벨에 의해 먼저 선택된 표본이다

- `scripts/build_corpus_shard.py`는 먼저 주 라벨로 `build_tabular_Xy`를 호출한다. 무승부 등으로 제외된 행은 `used`에 없다.
- 보조 라벨은 이후 `used`에 대해서만 계산한다. 예를 들어 event 무승부지만 lex 승패가 있는 교전은 event 주 샤드의 lex 평가에서 복구되지 않는다.
- 따라서 각 라벨의 독립 전체 코퍼스 성능과 동일 표본 비교를 혼동하면 안 된다. 라벨별 제외로 경기별 표본 수가 달라지면 GroupKFold 배정도 달라질 수 있다.
- 수정안: 특징 유효성에 따른 공통 모집단을 먼저 만들고, 각 라벨/무승부 마스크를 별도 저장한다. 독립 유효 표본 평가와 교집합 평가를 구분하고 match→fold 매핑을 고정 저장한다.

- 수정안: 챔피언/룬/주문/밴 ID만 범주형인 변형을 주 비교로 하고, 아이템 카운트 범주형 변형은 별도 명명한다. 범주형 대상 열 이름도 산출물에 기록한다.

## 7. [P2, 측정 한계] 가격 회귀의 R²는 실제 사건별 지급액의 정당성을 보장하지 않는다

- `analysis/event_prices.py`는 분 단위 골드 증가를 사건 개수와 CS 증가로 OLS 회귀하고, 그 계수를 가격으로 사용한다.
- 이는 조건부 평균 회귀 계수다. 누락된 경제 요인·사건 동시 발생·미니언/정글 조합·패치/시간 효과가 계수에 포함될 수 있다. “규칙에 따른 정확한 지급액”과는 다르다.
- `fit_prices`의 SE는 일반 OLS 잔차 공분산이며, 같은 경기 내 반복 구간의 상관을 반영하지 않는다. 문서의 SE를 게임 규칙 가격의 불확실성으로 읽으면 안 된다.
- 학습에 사용한 구간에서 계산한 R²이며, 가격 추정 경기를 예측 평가 모집단에서 격리하는 절차도 현재 스크립트에는 없다. 이것을 곧바로 예측 특징 누수라고 부를 수는 없지만 라벨 구축과 평가의 독립성은 명시해야 한다.
- 수정/검증안: “회귀 추정 사건 골드”로 표현, 경기 단위 홀드아웃 잔차 평가·클러스터 부트스트랩, 가격표 학습 데이터 고정, 규칙표/무가격/추정가격 라벨의 감도 비교. 계수를 먼저 임의 수정하지 않는다.

## 추가 점검 항목

- `_lex_refine`의 생존자 값은 `interpolate_node_global`의 분 프레임 유지값이다. 마지막 킬 시점의 정확한 생존자 수라는 표현은 강하다. 이 판정 단계의 사용 비율과 이벤트 기반 보정 민감도를 확인해야 한다.
- 좌표는 관측창 초반에서 cutoff 이전의 두 프레임 사이를 보간할 수 있다. cutoff 이후 누수는 아니지만 “모든 입력 위치가 단순 유지”라는 설명은 정확하지 않다.
- `frame_age_s`는 마지막 구간 중심의 global snapshot 기준이며 60초로 클립된다. “cutoff까지 도착한 마지막 프레임의 나이”와 다르다. 실제 의미로 명명하거나 정의를 맞추고 재평가한다.
- 존재 게이트의 R=1600과 위치 유지 오차의 규모가 비슷하다는 점은 문서에 이미 한계로 기재돼 있다. 규칙 반경의 정확성과 실제 위치 판정의 정확성은 구분해야 한다.
- 규모에 따른 AUC 차이를 규모 자체의 인과효과로 읽으면 안 된다. 게임 시간·경제 격차·참여 불균형 등을 맞춘 비교가 필요하다.
- 같은 코퍼스로 정의를 추정한 뒤 같은 코퍼스 OOF를 수행한 결과는 현재 분포 내부 예측력이다. 새 패치 일반화 주장은 정의/가격을 고정한 외부 평가로 별도 뒷받침해야 한다.

## 검증 결과와 실행 순서

Anaconda Python 3.13.5로 기존 핵심 회귀 테스트 16개 통과(8.27초): frame alignment, absolute time, causal anchors, absolute spatial XY, market event label, config overrides. 기존 `.venv` 대신 실행 가능한 런타임을 사용했다. 전체 테스트 통과를 뜻하지 않는다.

추가 합성 재현으로 마지막 킬 제외에 따른 라벨 반전과 plan 특징 이름 유실을 확인했다. 위 재현은 전체 코퍼스의 영향률을 추정하지 않는다.

권장 순서:
1. 끝점 계약과 특징 이름 결함에 실패 회귀 테스트를 추가하고 수정한다.
2. 샤드 무결성 검증과 실효 설정 manifest를 추가한다.
3. 현재 v3.2 산출물을 기준 스냅샷으로 보존하고, 별도 버전에서 영향률을 측정한다. 진행 중인 파일을 섞어 쓰지 않는다.
4. 전역/교전 라벨 귀속과 다중 라벨 모집단을 명시한 비교를 수행한다.
5. 가격 불확실성·범주형 변형·규모 교란을 검증한 뒤 최종 수치와 논문 문구를 확정한다.
