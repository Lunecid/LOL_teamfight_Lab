# 폴더 정리 이후의 비용 측정과 학습

이번 변경은 EPT 파일 배치를 정리한다. 기존 S CPU 실측을 새 코드의 속도라고 해석하거나, 기존 실행에 새 코드를 덮어써서 이어 돌리는 변경이 아니다.

## 작업 폴더와 실행 폴더

개발 통합은 `codex/modularize-three-projects` 브랜치에서 한다. 저자가 선택한 IDE 폴더 `LOL_teamfight_new-c-ept-s4`에도 최신 구조와 기존 주석을 보존해 반영했으며, 이 폴더는 현재 개발 복사본이다. 이전 비용 측정의 코드 커밋과 로컬 변경은 별도 backup ref·stash·파일 백업으로 보존했다. D 드라이브의 과거 run·입력·실측은 그대로 둔다. 현재 배치는 [모듈 지도](../MODULES.md)와 [EPT 안내](../c_ept/MODULES.md)를 따른다.

다음 실제 측정 전에 검토된 커밋으로 전용 실행 체크아웃을 만들고, 편집 작업은 개발 체크아웃에서만 한다. 실행 중에는 전용 체크아웃의 소스·문서·환경 파일을 수정하지 않는다. 기존 전체 저장소 청결 검증은 계속 적용한다.

## 남은 실행 결정을 구분한다

1. 기존 S CPU 두 에폭의 부분 실측과 실패 원인 보고를 보존한다. COST.json이 없으므로 G-S4a는 아직 완료되지 않았다.
2. 저자가 승인한 GPU 비용 범위는 v2 `gpu_cost` profile의 S/M CUDA·두 에폭·25%·DEV 200행이다. 기존 v1 CPU/CUDA 전체 조합은 그대로 유지한다. 검토된 operator를 사용하며 하위 runner를 직접 불러 계약을 우회하지 않는다.
3. M CPU의 짧은 측정은 아직 이번 실행 범위가 아니다. GPU profile 완료와 원래 CPU 포함 전체 격자 완료를 구분한다. M CPU 비용이 없는 곳은 미측정으로 표시하며, 조건부 외삽과 실측을 분리한다.
4. 새 실행은 새 run identity로 기록한다. 기존 실패 run에 새 코드 커밋을 넣어 Resume하지 않는다. 완료 단계나 체크포인트를 새 run의 연속 실측으로 옮기지 않는다.
5. G-S4a에서 보고 장치·모델 크기·에폭 예산·S4b 범위를 정한 뒤 목적 성능을 확인하는 S4b 학습을 시작한다. 최종 선택 설정의 반복·제거 실험은 S7이며 TEST 1회 평가는 S8이다.

이 문서는 다음 실행 준비 사항이다. 파일 정리와 합성 회귀 검사만으로 실제 학습이나 비용 측정을 새로 시작하지 않는다. CPU 전체 비용의 조건부 외삽을 GPU 실측 또는 성능 검증으로 대체해서 설명하지 않는다.

2026-10-24 저자가 GPU 비용 측정을 새 실행 폴더에서 진행하도록 승인했다. 이 문서의 미지원 상태는 v1 당시 상태이며, 검토된 v2 gpu_cost profile로 S/M CUDA를 측정한다. [추가 실행 계약](superpowers/plans/2026-10-24-task8-gpu-cost.md)이 현재 범위다. IDE 폴더 LOL_teamfight_new-c-ept-s4는 저자의 요청으로 최신 구조를 적용한 개발 복사본이며, 보존된 로컬 주석 때문에 실제 측정에는 별도의 깨끗한 checkout을 사용한다.
