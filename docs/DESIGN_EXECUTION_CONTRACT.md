# 설계와 실행 역할 분리

사용자 지시: 계획은 현재 Codex 대화에서 수립하고 Claude에서 구현·실행한다. 구현을 정확히 수행할 수 있다면 경량·낮은 토큰 모델을 사용해도 된다.

## 역할

- Codex: 연구 질문, 정의, 입출력 계약, 문헌 근거, 실험 조건, 완료 기준 수립. Claude 결과를 원본 산출물과 대조하고 후속 작업을 결정한다.
- Claude: 전달된 명세에 따른 코드 구현·테스트·실험 실행·로그와 산출물 저장. 연구 표적이나 분할, 평가 기준을 임의 변경하지 않는다.
- 실행 중 명세 변경이 필요하면 근거와 가능한 수정안을 반환한다. 단순 구현 오류는 명세 안에서 수정하고 변경 내역을 기록한다.
- 사용자에게 같은 실행 승인을 반복해서 요청하지 않는다. 이미 승인된 범위 내에서 명세 전달, 실행 결과 회수, 검증을 진행한다.

## 실행 모델과 비용

- 특정 Claude 모델에 고정하지 않는다. 정확한 구현이 가능한 경량 모델을 우선한다.
- 전체 대화나 원고를 매번 넘기지 않고 작업별 명세, 필요한 파일, 입력·출력 스키마, 검증 기준을 전달한다.
- 모델 이름보다 산출물·테스트·재현성을 기준으로 완료 여부를 판단한다.
- 이 문서는 실행 모델을 실제로 변경했다는 기록이 아니다. 실제 실행마다 사용 모델/도구, 명령, 로그, 종료 상태를 남긴다. Claude 실행 경로를 사용할 수 없으면 다른 실행자를 Claude라고 표현하지 않는다.

## 전달 단위

각 작업은 목적, 수정 허용 범위, 입력/출력 경로, 고정 조건, 검증 명령, 완료 기준, 반환 요약을 포함한다. 원본 결과와 새 결과는 다른 버전/폴더로 보존한다. 현재 실행 중인 Claude 작업을 재시작하거나 덮어쓰지 않는다.

## 다음 실행의 범위

다음 우선 작업은 **수정된 상태 스키마로 독립 V2 재학습·보정**이다. 세부 계획은 [현재 정합성 및 다음 작업](CLAUDE_CURRENT_ALIGNMENT_AND_NEXT_STEPS_20260914.md)의 P1을 따른다.

- 신규 입력은 `gameplay.state_value_v2.StateBuilder`와 `objective_history_v2_participant_order`를 사용한다.
- 기존 V fit/calibrate/select/test의 경기 분리를 유지하고 새 상태로 각 분할을 재생성한다. 이미 생성한 교전 상태 26,693행을 V 학습 자료로 사용하지 않는다.
- v1 모델·라벨·결과는 보존한다. V2 검증 이후 B60/90/120 라벨 재생성과 q 재학습을 별도 작업으로 진행한다.
- 반환에는 모델/상태 버전, 분할 중복 검사, 영혼 원소 특징 확인, 전체·시간대·오브젝트별 확률 품질, v1 대비 비교, 오류와 미완료 항목을 포함한다.

상태: 운영 원칙 확정. 이 문서 생성만으로 Claude에 다음 실행이 전달되거나 실행이 시작된 것은 아니다.
