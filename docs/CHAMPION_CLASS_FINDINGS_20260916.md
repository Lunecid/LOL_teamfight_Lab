## 3. 왜 아무것도 안 나오는가

- **라벨의 구조**: Y는 동결 V의 Δlogit = βᵀΔt(S) 부호이고(V 분해 단계), 90 s 안의 킬·골드·오브젝트 변화가 좌우한다. 챔피언 항은 가산이라 정확히 상쇄되므로 조합은 "누가 그 변화를 만들어내는가"를 통해서만 들어올 수 있는데, 조합 단독 AUC 0.50은 그 경로가 비어 있음을 뜻한다.
- **상태가 이미 흡수**: 슬롯 = 포지션이므로 LightGBM은 "미드 슬롯의 레벨·골드"를 이미 분기 조건으로 쓴다. 그 슬롯이 암살자인지 메이지인지 알려 줘도 분기가 달라지지 않았다(class_state·class_pairs 무효). "잘 큰 암살자"의 효과가 있다면 "잘 큰 미드"에 이미 포함돼 있다.
- **정체성도 무효**: 챔피언 one-hot 1,710열도 LightGBM에서 0 차이. 5인 조합이 경기마다 고유해(68,712/69,124) 챔피언 단위 시너지는 학습 불가능하고, 클래스 단위는 밀집하지만 신호가 없다.
- **logistic 악화**: C가 352열 승자(0.001/0.01)로 고정돼 열이 늘수록 과적합. 이는 설계상 한계(재탐색 없음)이며 LightGBM 결론과 무관하다. N LightGBM class_state는 반복 상한 1,000에 닿았다(999/1000/1000).

## 4. 함의 (사용자 제안에 대한 답)

1. 챔피언 조합·클래스는 이 표적(90 s ΔV 부호)에서 **이미 학습된 바 없고, 학습할 것도 없다.** 표 형식 학습기에 명시적 클래스×상태 열을 주어도 0이면, 같은 정보를 그래프로 표현한 Track B 어댑터가 찾아낼 신호는 없다 — Track B는 조합 목적으로는 만들지 않는 것이 맞다.
2. 조합이 의미 있으려면 표적이 달라야 한다(예: 경기 최종 승패의 드래프트 예측, 교전 *발생*·개시 예측, 또는 능력치 수준의 표현). 이 결과는 "한타 결과의 예측 가능성은 사전 상태(경제·전투·오브젝트)에 걸려 있고 조합은 그 위에 얹을 것이 없다"는 문장으로 원고에 쓸 수 있다.
3. 라이엇 태그(6종)는 거친 분류이지만, 정체성 one-hot(가장 세밀한 표현)도 0이었으므로 세부 클래스(13종)로 내려가도 결과가 바뀔 근거는 없다.

## 5. 검증

- 절차: 스냅샷 → 계약 테스트(10) → 프로토콜(팔·블록·어휘 171·태그 표 sha·주 비교 사전 등록) → smoke(TRAIN 1/8, 32 적합) → 테스트 → 전체 적합 32 → 동결 → 봉인 평가 → 사후검증 → 보고서. 첫 smoke 적합은 재로딩 동일성 게이트에서 실패(열 인덱싱이 F-order 배열을 만들어 마지막 비트 3e-16 차이) → `bundle_raw`를 C-연속 입력으로 고정, 영수증 `audit_followup/RELOAD_IDENTITY_LAYOUT_RECEIPT.json`.
- 사후검증 1·2차 실패는 "base 팔이 부모 iq 승자를 재현하는가" 검사의 허용 오차였다: LightGBM은 모든 세트에서 정확히 0, logistic은 raw에서 6e-7(T)~3.4e-5(N). 같은 행·가중·코드로 C-order 설계로 다시 적합하면 이 실행과 비트 단위로 같고(0.0), 부모식 F-order로 적합하면 507회 반복(이 실행 483회)으로 1.9e-5 떨어진다 — lbfgs(tol 1e-8)의 수치 경로 차이이지 자료·코드 불일치가 아니다. 검사를 raw 수준 LightGBM 정확/logistic 1e-4로 나누고 실패 파일과 실험을 `audit_followup/POSTRUN_CHECK_CORRECTION_RECEIPT.json`에 남겼다. 이 실행 안의 모든 팔은 한 경로에서 적합됐으므로 대비에는 영향이 없다.
- 데이터: 21만 경기 코퍼스 + 외부 4세트 그대로. Data Dragon 26개 버전 승인 다운로드(`ddragon/`, 태그 변경 Shyvana 1건, 신규 Zaahen·Locke).
- 하지 않은 것: MLP/GPU 팔, 세부 클래스, Track B 그래프, V·라벨 변경, 인과 해석.
