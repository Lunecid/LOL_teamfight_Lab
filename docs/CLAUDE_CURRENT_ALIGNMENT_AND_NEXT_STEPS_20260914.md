## 이번 수정

새 모듈: [state_value_v2.py](../worktrees/engagement-state-value/gameplay/state_value_v2.py).
버전: `objective_history_v2_participant_order`.

1. **영혼 종류:** 실제 Match-V5의 `name`과 기존 `dragonSoul`/`soulType`을 처리한다. Cloud/AIR, Mountain/EARTH, Infernal/FIRE, Ocean/WATER, Hextech, Chemtech를 정규화한다. 서로 모순되는 알려진 종류는 조용히 선택하지 않고 해당 시점에서 오류로 처리한다. 미지 종류는 OTHER로 남긴다.
2. **팀 미식별 영혼 이벤트:** teamId가 100/200이 아닌 이벤트를 팀의 영혼 획득으로 만들지 않는다. 별도 시점별 진단 수로 보존하고 일반 오브젝트 오류 카운트와 분리한다. 이 이벤트를 ‘지형 변경’이라고 추측해 다른 정답으로 만들지도 않는다.
3. **사후 역할 의존 제거:** `role_slots`, `teamPosition`, `individualPosition`을 사용하지 않는다. 팀 순서(blue/red), 팀 안의 숫자 participant ID 순서로 고정한다. 이름을 `slotN_*`에서 `participant_slotN_*`로 바꿔 TOP/JUNGLE 등의 의미로 해석하지 않게 한다.
4. **시점 보존:** q 이하 이벤트만 상태에 반영한다. 미래의 영혼 필드 충돌이나 경기 최종 승패가 이전 상태에 영향을 주지 않게 한다.
5. **혼용 방지:** `StateV2`와 `state_matrix()`에서 버전·정확한 특징 순서를 검사한다. 새 입력을 기존 v1의 계수·V·SHAP에 붙여 사용하면 안 된다.

기존 `gameplay/state_value.py`는 frozen v1 재현용으로 보존했다. 단순히 함수를 덮어쓰면 저장된 동일 모델 파일이 다른 의미의 입력을 받아 과거 결과 재현이 깨진다. **향후 신규 학습 코드는 `gameplay.state_value_v2.StateBuilder`를 사용해야 한다.** 기존 실행 스크립트는 과거 실험 재현 경로다.

참가자 ID/팀 자체도 서비스에서는 경기 시작 시점에 가용한 로스터로 공급해야 한다. 이번 수정은 사후 역할 메타데이터 의존을 제거한 것이며, Riot 공개 API의 라이브 제공 가능성을 증명한 것은 아니다. 역할별 코칭 해석은 당시 가용 역할 정보가 별도로 검증될 때만 복원한다.
