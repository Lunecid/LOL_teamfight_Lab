# 개발 패치 전용 정의(G 14.0 s, D 4,285 u)로 재탐지해도 결과는 그대로다 — 결과와 해석

2026-09-16. 설계·구현·실행·검증: Claude(Codex 라인 계승). 감사 문서 §5의 "정의 상수 G/D가 15.16(TEST)까지 포함해 추정됐다"는 분할 제한과 비판 대응 §7-3(TRAIN-only G/D 재탐지)에 대한 실행. 명세 `CLAUDE_DEFINITION_DEV_20260916.md`, 실행 `outputs/definition_dev_20260916/`. 사후검증 53/53(3차 통과; 1·2차는 조사 일관성 검사의 불변식 오류 — 교전을 전부 잃은 경기 88건(TRAIN)·59건(TEST)을 "재탐지 누락"으로 오해 — 로 실패, 영수증 `audit_followup/POSTRUN_CHECK_CORRECTION_RECEIPT.json`).

**판단:** 한타 정의 상수를 합동 추정치(13.7 s / 4,264 u) 대신 TRAIN 패치 15.14 단독 추정치(13.96 s / 4,285 u → 같은 반올림 규칙으로 14.0 s / 4,285 u)로 바꿔 21만 경기와 외부 4세트를 다시 탐지하면 **경기의 3.3–4.4 %가 바뀌고 노출 행의 1.9 %가 제거·1.2 %가 추가**되지만, 동결 모델의 봉인 지표는 소수점 넷째 자리까지 같고(TEST T LightGBM Brier 0.22839 → 0.22837, AUC 0.6691 → 0.6691), 새 모집단에서 다시 적합한 LightGBM은 동결 모델과 구별되지 않는다(주 대비 ΔBrier −0.00007 [−0.00023, +0.00010]). 학습기 순서(LightGBM ≈ logistic > PT)와 균형 셀의 결론도 그대로다. 즉 pooled 정의를 쓴 것이 TEST 패치에 유리하게 작용했다는 증거는 없다.

## 1. 기계 검증

- 부모 탐지 코드(`gameplay.fights.detect_fights` → `_fight_to_ref_row` → `analyse_match`)를 동결 상수로 TRAIN 2,000경기에 돌리면 부모 `exposures.csv`와 **정확히 일치**(5,247행, 불일치 0); 재탐지 클러스터 인원과 부모 코호트 n_min도 5,247/5,247 일치.
- 부모 노출로 재구축한 100경기(250행)는 부모의 입력 362열·p_pre·p_post·라벨·유효 플래그와 **비트 단위 일치**(fixture). 따라서 8필드 노출 튜플이 같은 행은 두 정의에서 동일하고, 바뀐 경기만 재구축하면 된다.

## 5. 해석과 논문 문장

- 정의 산출에 TEST 패치가 들어갔다는 우려는 실측으로 닫힌다: 개발 패치 단독 상수는 pooled 상수와 0.3 s / 21 u 차이이고(둘 다 ARI 평원 10–18 s와 D 신뢰구간 안), 그 차이로 바뀌는 교전은 2 %, 지표 변화는 0.0000–0.0002, 학습된 q의 변화는 구간 0 포함이다.
- 논문에는 "정의 상수는 15.14–15.16 합동 추정치이며, 학습 패치만으로 추정한 상수(14.0 s / 4,285 u)로 재탐지하면 교전의 2 %가 바뀌고 봉인 Brier는 0.0002 안에서 같다(재적합 − 동결 −0.00007 [−0.00023, +0.00010])"로 쓸 수 있다. 두 모집단의 지표 차이는 서술적 비교이고, 정의 변경의 "순수 효과"라 부르지 않는다.
- 남은 열린 부분: 15.14 + 15.15 합동 추정치는 만들지 않았고(패치별 명세만 존재), 정의의 다른 스위치(병합·길이 제한·presence)는 바꾸지 않았다.
