# 프로젝트 작업 지침

2026-10-24까지 저자가 정한 현재 작업 원칙을 모았다. EPT, CoG, Master/ToG와 공통 실행 도구에 적용한다. 이 문서는 기존 설계서·단계별 계약의 요약 진입점이며, 연구 정의를 새로 승인하는 문서가 아니다. 이후 저자의 명시적 지시는 관련 이전 합의를 갱신한다. 전역 에이전트 설정이나 메모리 파일은 이 작업으로 변경하지 않는다.

## 1. 역할과 모델 사용

- Codex는 설계·범위 결정·통합·최종 검증을 맡는다. 구현자와 독립 검토자를 분리한다. 구현자가 스스로 통과라고 보고한 것만으로 독립 검토를 대신하지 않는다.
- 현재 구현 보조는 Sol 6.1을 활용한다. Sonnet을 사용할 수 있다는 가정으로 작업을 배정하지 않는다. 단순 조회·계산·기계적 변환은 직접 도구를 우선하고, 간단한 구현·주석·설명에는 낮은 모델과 Gemini를 활용한다.
- Gemini는 **OpenCodex**의 기존 연결을 사용한다. OpenCode와 혼동하지 않는다. 기존에 승인된 필요한 코드·문서 발췌 또는 파일명·역할 요약만 보내고, 비밀정보·원시 경기 데이터·가중치·보호된 분할 본문은 보내지 않는다. 다른 종류의 미승인 자료로 전송 범위를 확장하지 않는다.
- Strata는 계속 **OFF**다. 일반 로컬 지침의 자동 시작 허용보다 이번 저자 지시가 우선한다. 건강 검사나 기본 fallback을 이유로 시작하지 않는다.
- 외부 모델의 연결·플랜 제한을 우회하거나, 계정·설치를 임의로 바꾸거나, 다른 모델을 Gemini라고 표시하지 않는다. 실패·시간 초과·잘린 응답은 사실대로 기록하고 반복 호출로 해결하지 않는다.
- 모델 초안은 근거 자료다. 설명·주석·코드의 중요한 주장은 원문과 시험으로 확인한다. 부분 응답의 완성된 문장만 활용한 경우 전체 작성·전체 검토로 표현하지 않는다.

## 2. 범위와 연구 정의

- 승인된 작업서에서 출발하고 지정 파일부터 읽는다. 파일 검색은 좁혀 수행하며 긴 로그·반복 diff·저장소 전체를 불필요하게 읽지 않는다.
- 라벨·분할·시간 경계·평가 분모·가중·확률 족·연구질문·동결 모델·난수 계약을 파일 정리나 최적화 명목으로 바꾸지 않는다. 연구 변경은 저자의 별도 판단 대상이다.
- EPT는 교전 발생과 표식, 조건부 결과, 전환을 연결해 가치를 합성한다. V_start와 V_window의 시간 정의를 구분한다. 합성 가치나 골드 기대값을 곧바로 승리 확률·인과 효과로 설명하지 않는다.
- CoG의 구 계보와 Master/ToG의 새 계보, EPT 현재 연구를 섞지 않는다. 날짜별 연구·잠금 수치·과거 결과를 하나의 새 정의로 통합하지 않는다.
- 기존 사용자·다른 에이전트의 변경을 되돌리거나 출처 확인 없이 덮어쓰지 않는다. 주석만 바뀌었더라도 실제 diff·검증을 보지 않고 동작 동일성을 확정하지 않는다.

## 3. 파일·데이터 보호

- `c_ept/cohort.py`, `research_pipeline/cohort_policy.py`, `research_pipeline/holdout_r3/`의 보호된 본문은 열거나 수정·전송하지 않는다. 경로·기록된 해시·허용 메타데이터로 필요한 범위를 확인한다. 시험은 필요한 경우 실패 sentinel 또는 작은 stub을 사용한다.
- 원시 경기 데이터·비밀정보·가중치·체크포인트 payload·대형 NPZ/joblib을 임의로 열지 않는다. 비용·진행 확인에는 RUN/STAGES/PROCESS와 요약 JSON 등 허용된 작은 메타데이터를 사용한다.
- 체크포인트 head JSON을 확인하는 것과 실제 가중치를 읽어 reload·검증하는 것은 다르다. 기록·해시 일치만으로 payload 검증을 완료했다고 하지 않는다.
- CoG 원고·LOCK·CONTRACT·REVIEW_RESPONSE·RESPONSE_EVIDENCE_MATRIX의 기존 수치 행을 삭제·수정하지 않는다. 허용된 추가 주석과 실제 연구 수치 변경을 구분한다. `master_ver/legacy_oldlineage/docs/tog_manuscript/`는 읽기 전용이다.
- Master 수치 검증의 근거는 원본 작업공간이다. 원본 동기화는 기존 sync 도구의 계약을 따른다. 저자가 승인한 모듈화 파생 트리는 예외적으로 코드 배치를 변경한 상태이며, module-layout marker가 있는 트리에 sync `--apply`를 강행하지 않는다. 별도 원본 mirror에서 갱신 후 차이를 검토한다.

## 4. 부품화와 코드 변경

- [모듈 지도](../MODULES.md)를 현재 구현 위치의 진입점으로 쓴다. EPT는 data, preprocessing, domain, models, ept, valuation, workflows, reporting, checks, runtime으로 역할을 나눈다.
- 이전 import/module 명령의 호환 파일은 `_compat/`에 모은다. 같은 계산 코드를 두 벌 유지하지 않는다. 새 코드는 canonical 구현 폴더를 사용한다.
- 호환성이 필요한 import는 같은 모듈 객체·globals·monkeypatch 상태를 유지한다. 직렬화 이름과 CLI, 파일 상대 경로, 리소스·저장소 기준 경로, 패키징 포함 여부를 함께 확인한다.
- EPT 루트의 옛 `.py` 직접 파일 경로는 제거됐다. 기존 `python -m c_ept.<module>` 및 수동 wrapper 계약은 보존한다. 외부 직접 파일 실행은 지원 module 명령으로 바꾼다.
- 구성·고정 legacy 리소스·runlog·보호된 cohort의 위치 기준을 함부로 옮기지 않는다. 초기화 보조 코드는 수치 라이브러리보다 먼저 적용할 수 있도록 가볍게 유지한다.
- 구조 정리에서는 수학·분할·난수·dtype·스레드·체크포인트 스키마를 유지한다. training 경로에서 계산을 생략해 dropout/RNG 진행이 달라지는 최적화를 무심코 적용하지 않는다. 평가 전용 최적화와 실제 학습 최적화를 구분한다.
- 과거 방정식·기호·해시 인덱스는 당시 기록으로 보존하고, 현재 경로 등록부를 별도로 연결한다. 주석은 새 부품의 역할·입력·출력·단위·조건·한계를 실제 코드에 맞춰 설명한다.

## 5. 검증과 독립 검토

- 버그 수정은 재현 조건, 파일 이동은 import·CLI·직렬화·리소스 경로·패키징 등 실제 위험을 검증한다. 무의미한 구현 복사 시험이나 불필요한 광범위 재시험을 늘리지 않는다.
- 합성 소프트웨어 검사는 GPU OFF·native 1스레드·bytecode/cache 억제와 명시적 UTF-8 환경을 사용한다. 이 시험 설정을 과학 학습의 CPU 8스레드·float32·고정 시드 계약으로 혼동하지 않는다.
- 이동한 구현을 AST·명시적 예외·적절한 기존 회귀와 대조한다. 소스 스캔 시험은 호환 파일 대신 실제 구현을 보게 하고 금지 조건을 그대로 유지한다. 허용 목록 수정은 근거를 확인하고 기록한다.
- 구현자가 결과와 정확한 명령·실패·미실행·한계를 남긴 뒤 변경을 동결한다. 독립 검토자는 원본 차이와 별도 probe로 확인하고 발견 사항을 구현자에게 돌려보낸다.
- 큰 로그는 로컬 `work/`에 두고, 공유할 검토·결과 요약은 docs에 남긴다. 여러 실행의 누적 통과·중복 사례·한 번의 최종 전체 통과를 구분한다. 실패 로그를 지우거나 미실행을 통과로 바꾸지 않는다.
- 테스트·해시·장부 일치만으로 전체 프로젝트 무오류, 과학적 타당성, 수치 결과 동등성 또는 실제 환경의 완전한 재현을 주장하지 않는다.

## 6. 실행 폴더와 사용자 단독 실행

- 개발·주석·구조 변경용 checkout과 실제 측정용 checkout을 분리한다. 실제 실행은 검토된 커밋으로 고정한 깨끗한 전용 checkout에서 한다.
- 실행 중 소스뿐 아니라 문서·wrapper·환경 파일도 바꾸지 않는다. 저장소 전체 청결 검증을 주석 예외나 guard 완화로 통과시키지 않는다.
- 기존 비용 실행 checkout·입력·run·원본 환경을 개발 배치로 덮어쓰지 않는다. 실패한 run의 identity를 새 커밋에 맞게 재작성하거나 완료 단계를 새 연속 실측처럼 옮기지 않는다.
- 사용자가 에이전트 없이 실행할 수 있도록 고정 Python, 환경 계약, 설정 예시, Check/Start/Resume/Status와 출력 위치를 문서화한다. 기본 동작은 읽기 전용 Check다. 새 설치·환경 변경·Start/Resume를 문서 조회나 상태 확인에 끼워 넣지 않는다.
- 현재 패키지는 외부 고정 자산과 저장소 설정이 필요한 source-backed 실행이다. wheel import/help 성공을 자료·고정 자산이 포함된 완전한 연구 환경이라고 설명하지 않는다.
- 새 장시간 실행·재학습·재집계·S4b 이후 단계는 저자가 정한 단계 승인에 따른다. 범위가 분명한 승인에 대해 반복 확인을 요구하지 않되, 코드 수정 요청만으로 새 연구 실행 범위를 만들어내지 않는다.

## 7. Task 8과 학습 관문

- 비용 측정은 S4a/Task 8이고 **G-S4a에서 멈춘다**. S4b/S6/S7을 자동 시작하지 않는다. 최종 목적의 성능 학습과 비용 측정을 구분한다.
- 이전 Task 8은 scales, stats, S CPU까지 완료한 뒤 저장소 청결 검사에서 실패했다. COST가 완성되지 않았으므로 G-S4a는 미완료다. 해당 감시는 종료·삭제된 상태이며 중복 실행하거나 새 감시를 임의로 만들지 않는다.
- 현재 수동 operator는 S/M × CPU/CUDA, 두 에폭, 25%, DEV 200행 계약을 검증한다. GPU 우선 또는 M CPU 짧은 측정은 별도 실행 계획·설정 계약 검토 사항이다. 설정만 바꾸거나 하위 runner를 호출해 operator 경계를 우회하지 않는다.
- 다음 실행에서는 새 커밋·설정·환경·입력 identity와 원래 부분 실측을 구분한다. 기존 실패 run의 Resume가 가능하다고 가정하지 않는다.
- G-S4a에서 보고 장치, 모델 크기, 에폭 예산, S4b 범위를 저자가 정한다. CPU 보고 모드의 재현 계약과 GPU 비용·탐색 모드를 구분한다. 보고용 GPU 전환은 저자 결정 대상이다.
- S4b는 설계 점검, 25% 멈춤 규칙, 학습 곡선과 시드 변동을 다룬다. 승인된 예산에서 60초 발생 Brier의 B1 비교를 수행한다. 비용용 두 에폭만으로 설계 성공·실패나 수렴을 판정하지 않는다.
- 이후 S5 기준·epsilon 잠금, S6 크기/하이퍼파라미터 탐색, S7 선택 설정·제거 실험 반복, S8 TEST 1회·외부 평가 순서를 따른다. 보류된 TEST/CAL/AUDIT를 상태 확인이나 탐색에 임의로 열지 않는다.
- 한 번 학습 24시간 및 40 GiB 예산을 지킨다. 짧은 실측 외삽으로 전체 학습을 측정했다고 표현하지 않는다. 원시 FIT 전체 확장은 학습 곡선 근거와 별도 승인 대상이다.

## 8. 결과 보고와 시각화

- 새 실제 결과·완료·실패가 생기면 한국어 요약과 보고서·표·JSON·시각화를 준비한다. 출처·커밋·설정·해시·표본·단위·분모·가중을 연결한다. 상태가 같은 감시는 조용히 유지한다.
- 실행 중 보고는 가벼운 메타데이터·표·상태 SVG 등으로 만들고, 무거운 수치 렌더링은 실행 종료 뒤에 한다. 실제 그림을 열어 원본 수치·축·레이블·단위·누락 표시와 대조한다.
- 실측과 조건부 외삽, 점 추정과 시나리오·신뢰구간을 구분한다. 현재 run의 시간은 해당 코드·환경·동시 활동에 묶는다. 새 모듈화 코드나 GPU의 속도로 돌려 말하지 않는다.
- 프로세스 private 표본 최대, 관측 lifetime upper, legacy RSS, GPU allocated/reserved를 구분한다. 표본 관측을 연속 상한 증명이라고 하지 않는다.
- 전체 호출·에폭·STEP·forward/loss·backward·optimizer·저장 시간의 중첩과 포함 범위를 표시한다. 중첩 성분을 전부 더하지 않는다. 실제 checkpoint write와 serialization·복사 비용도 구분한다.
- 미측정은 unavailable이며 0이 아니다. 종료 표지와 실제 PID/생성 시각을 대조한다. lock 파일 존재만으로 생존을 단정하거나 삭제하지 않는다.
- recovered/resumed 실행을 중단 없는 성능 보정으로 쓰지 않는다. 동시 개발·검증 활동이 있었다면 배타적 호스트 계측이라고 표현하지 않는다.
- 학습 숫자는 epoch의 0/1 기반 표기와 선택 기준을 확인한다. head 메타데이터의 선택 epoch·유한성만으로 손실 개선량·일반화·수렴·기준선 우위를 단정하지 않는다.

- README는 자연스러운 **영어를 메인**, 한국어를 보조 문서로 둔다. 연구 목적·사용 순서·부품 역할을 먼저 설명하고 상세 감사·검증은 연결 문서로 분리한다.
- 원고·수치·동결 문서는 별도 요청이 없는 한 수정하지 않는다. CoG 기존 작업서 규칙과 금지 주장 목록은 AGENTS.md의 기존 절을 계속 따른다.
- 현재 코드 정리의 commit/push 대상은 저자가 지정한 PUBLIC `Lunecid/LOL_teamfight_Lab`다. 이미 확인한 이 범위를 같은 이유로 다시 묻지 않는다. 향후 무관한 변경의 무제한 게시 승인은 아니다.
- 공개 게시에는 검토된 코드·테스트·필요한 문서만 담고, 원시 자료·가중치·비밀정보·고정 경기 membership·비공개 과거 Git 이력을 포함하지 않는다. 기존 공개 부모를 잇는 소스 스냅샷으로 정상 fast-forward한다. force push하지 않는다.
- pre-push 보호 훅을 전역 수정·해제하는 것을 일반 해법으로 삼지 않는다. 명시된 저자 승인과 해당 훅의 범위별 예외가 적용될 때도 공개할 파일·이력·제외 대상을 먼저 검증하고 실제 예외 사용을 기록한다.
- 검토된 소스와 게시한 Git blob을 확인한다. RAW 파일 해시와 Git 줄바꿈 정규화 후 blob 정체성을 혼동하지 않는다. 로컬 commit과 원격 push 성공을 구분한다.
- 완료 보고에는 변경 이유·실제 검증·한계·파일 링크·commit/push 상태를 남긴다. 중간 상태를 최종 완료로 보고하지 않는다.
